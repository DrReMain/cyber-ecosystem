# Recommended agent environment

An advice channel, not working-process law: the developer's coding agent surfaces these recommendations to the developer. The repo is fully functional without any tool listed here — each entry states what its absence degrades, so a developer can decide. Setup is manual by design: follow the upstream docs; an agent recommends but never executes the installation.

| Tool | Identity | Serves | Absent → |
|---|---|---|---|
| codegraph | npm `@colbymchenry/codegraph` — MCP server (`codegraph serve --mcp`) | edit-time context: symbol source, call paths, blast radius for indexed code | agents fall back to search-and-read loops — slower, no call-path view |
| memsearch | plugin from the `zilliztech/memsearch` marketplace | cross-session recall of past decisions, per-project collection under `.memsearch/` | semantic recall of history is gone; plain markdown remains readable |
| chrome-devtools-mcp | npm `chrome-devtools-mcp` — MCP server (`npx -y chrome-devtools-mcp@latest --auto-connect`) | driving live verification of web client surfaces (tanstack CONVENTIONS §11 reachable-surface rule) | live verification degrades to a manual developer walkthrough |
| react-devtools-cdt-mcp | npm `react-devtools-cdt-mcp` (official React team, experimental) — page-side library, wired per client through `@cyber-ecosystem/shared-devtools-mcp` | runtime React inspection for agents: component tree by stable uid, props and hooks values, source locations, per-commit render profiling | agents debug client surfaces by DOM only — no component-state view |
| tanstack-cli | npm `@tanstack/cli` — plain CLI (bin `tanstack`), not an MCP server | primary-source TanStack answers for agents: `search-docs` → `doc <library> <path>` doc pages, `libraries` for library IDs — all `--json` | framework-behavior calls (API shape, option semantics, version drift) rest on memory and code precedent, with no doc check |

Per-tool notes:

- **codegraph** — upstream: github.com/colbymchenry/codegraph. Per clone: `codegraph init` builds the index under `.codegraph/` (gitignored). Agents reach it through the codegraph MCP tools.
- **memsearch** — upstream: github.com/zilliztech/memsearch. Per-project state under `.memsearch/` (gitignored); installed and updated through the plugin marketplace.
- **chrome-devtools-mcp** — upstream: github.com/ChromeDevTools/chrome-devtools-mcp. Global npm install, MCP registration in the client config, plus the Chrome-side setup its README specifies. Launch with `--categoryExperimentalThirdParty=true` to enable the in-page third-party developer-tool channel (the React tools below ride on it).
  - Connection reality (Chrome ≥136): `--remote-debugging-port` no longer works on the default profile and `open --args` cannot retrofit a running instance — `--auto-connect` attaches only after the in-browser switch at `chrome://inspect/#remote-debugging` is flipped once (Chrome 144+; writes DevToolsActivePort into the default profile).
  - The attached session is the user's real browser: login state survives, but extensions inject console noise on some machines (fetch-wrapper and html-stamping families are handled app-side; expect their noise elsewhere).
- **react-devtools-cdt-mcp** — not an MCP server and never goes in the MCP client config: the page-side library registers its `react_*` tools through chrome-devtools-mcp's third-party channel. Wiring per client: `reactDevToolsMcp()` as the first vite plugin plus the `react-devtools-cdt-mcp` devDependency (the plugin's peer); the plugin prepends the register import to TanStack Start's dev client entry, so dev-only is structural — production builds never contain it. Traps: tools are discovered per page load — if the session attached after the load, reload the page once before diagnosing wiring; `includeHooks: true` dumps fiber internals wholesale — find the uid first, inspect one component; uids survive re-renders, not reloads.
- **tanstack-cli** — the agent's primary-source probe for TanStack framework behavior (API shape, option semantics, version drift). Per-clone: none — global npm install, or zero-install via `pnpm dlx @tanstack/cli@latest <cmd>`. Verified shapes (v0.72): `tanstack libraries --json` lists library IDs (`start`, `router`, `query`, `table`, …); `tanstack search-docs "<query>" --library <id> --framework react --json` locates the page (`results[{title, url, library, breadcrumb}]`); `tanstack doc <library> <path> --json` fetches it as `{title, content, url, version}` — full-page markdown, e.g. `doc start framework/react/overview`. Traps: `doc`'s first argument is a library ID — `query` there is TanStack Query, not a subcommand; `search-docs --library` does not strictly filter — confirm each result's own `library` field before trusting it. Scope: only the reference commands above are recommended — the CLI's scaffold family (`create`, `add`, `template`, `starter`) builds vanilla apps outside this repo's derive-from-skeleton paradigm and stays unused.
